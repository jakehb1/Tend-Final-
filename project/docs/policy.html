Policy & governance.

Attribute-based access control, row-level predicates, four-eye approvals, and an append-only audit log. The same gauntlet applies to a human, an agent, a webhook, or a connector. No exceptions.

The ABAC model

Every access decision is a pure function of four inputs: subject attributes, resource attributes, action, and environment. The policy engine evaluates rules in order until one returns a terminal verdict.

policypolicy "eu-pii-read" {
  target resource.tagged("pii") and resource.region == "eu"

  allow if subject.employment == "eu"
     and subject.training.gdpr >= "2025-12"
     and env.ip.country in eu_countries
     and env.purpose in ["support", "billing"]

  deny otherwise
}

Capabilities

Coarse-grained capability grants are the base layer. Fine-grained ABAC rules refine from there.

CapabilityGrants
read:allAll untagged fields across all entities

secret:readRead of fields tagged @secret. Never granted to agents.
write:scopedWrite to fields declared in the agent's manifest

Four-eye approvals

Any policy or any action can require a second, independent approval. The approver must satisfy a different predicate than the initiator. Same person cannot approve their own request.

policypolicy "production-write-agent" {
  target action == "agent.deploy" and env.target == "production"

  require approver {
    count:  2
    role:   "platform-admin"
    disjoint from subject
  }
}

Row-level predicates

Row-level rules narrow a resource set at query time. They're compiled into the query plan. There is no path that sidesteps them.

policyrow_policy "tenant-isolation" on Account {
  visible account.tenant_id == subject.tenant_id
}

Policy simulation

Before deploying a policy change, simulate it against historical traffic. The simulator replays the last N days of access requests and reports how each would resolve under the proposed policy.

shelltend policy simulate \
  --policy ./policies/eu-pii-read.v5.tend \
  --window 14d

# 142,081 requests replayed
# → 140,402 allow (unchanged)
# →   1,402 allow → deny (new restriction)
# →     277 deny → allow (relaxation)
# Top denied subjects: alex@... (40), bot:csm-watcher (38)

The audit log

Every access decision is recorded, append-only, with a cryptographic chain hash across records. A tampered record breaks the chain and is visible to auditors. Logs are exported to your S3/GCS bucket in batched Parquet.
