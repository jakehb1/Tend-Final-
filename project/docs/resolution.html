Entity resolution.

A three-stage hybrid pipeline. Deterministic keys first, probabilistic similarity second, human-in-loop confirmation for the long tail. Every merge is reversible, logged, and attributed.

The pipeline

resolution pipelinecandidate ──▶ block       # reduce N² comparisons via blocking keys
          ──▶ score       # deterministic + embedding similarity
          ──▶ decide      # auto-merge / defer / drop
          ──▶ commit      # write merge record + lineage

Deterministic rules

Express any number of deterministic rules. A match on any rule short-circuits scoring with full confidence. Rules are compiled to index lookups. They run in microseconds.

resolution/account.tendresolve Account {
  rule "salesforce_id"    = external.salesforce_id exact
  rule "domain_match"     = normalize_domain(primary_domain) exact
  rule "dunsbridge"       = external.dun_bradstreet exact
}

Probabilistic scoring

For candidates that don't hit a deterministic rule, the resolver emits a feature vector and scores with a per-entity-type model. The default model is trained on ~2.4B labeled pairs across the tend fleet; you can retrain against your own labels.

FeatureWeight (default)Signal
Name. Normalized Jaro0.28High for exact names, tolerant of case/punct
Domain. ETLD+1 match0.22Strong when present
Address. Geocoded proximity0.12Tolerates formatting drift
Industry. SIC/NAICS agreement0.08Weak but additive
Embedding. Description cosine0.18Catches paraphrases, aliases
Temporal. Co-occurrence0.12Rewards records seen together

Decision thresholds

ScoreActionDefault threshold
≥ τmergeAuto-merge, commit0.92
[τreview, τmerge)Queue for human review0.72
< τreviewDrop, log as negative pair
Tuning
Thresholds are per-entity-type. For finance entities (invoices, contracts) the defaults are higher; for support entities (contacts, tickets) they're lower. Override in resolve blocks.

The merge record

Every merge produces a first-class MergeDecision entity. It records the winning id, the losing id(s), the rule or model version, the score, and the principal (agent or human). Unmerge is tend merge reverse <id> and restores the prior state verbatim.

queryAccount.get("acct_4102").merge_history()

# [
#   { at: "2026-03-14...", kept: "acct_4102", merged: "acct_1984",
#     rule: "domain_match", score: 1.00, by: "system" },
#   { at: "2026-04-02...", kept: "acct_4102", merged: "acct_7721",
#     model: "acct-resolver@v12", score: 0.94, by: "agent:dedupe-v3" },
# ]

Human-in-loop

Items queued for review appear in the console and the CLI. A reviewer sees a side-by-side of the two candidates with differing fields highlighted, the score breakdown, and the resolver's confidence. One-click merge, split, or label-as-negative.

shelltend resolve queue --entity Account --limit 20
tend resolve approve q_8f2c --into acct_4102
tend resolve reject  q_8f2d --reason "different parent company"
