Docs overview.

tend is a four-layer platform — ontology, ingest, policy, runtime. These docs cover the concepts, the DSL, the APIs, and the operational envelope. Start with the mental model if you've never touched an ontology-native system before.

Quickstart

The fastest path from zero to a live ontology is four commands. You'll need a Python 3.11 runtime and a TEND_WORKSPACE_TOKEN from the console.

shell# install
pip install tend-sdk
tend login --workspace acme

# bootstrap a schema from your warehouse
tend init --from-warehouse snowflake://acme/prod

# push & compile
tend push
tend deploy --target staging
Note
First push takes 4–8 minutes for the planner to reconcile your schema against detected sources. Subsequent pushes are incremental (≤30s for typical diffs).

Versioning & stability

tend uses a two-track versioning model. The platform ships on a rolling two-week cadence with zero-downtime migrations. The ontology runtime API is pinned per-workspace and held stable for a minimum of 18 months from GA of each major.

  • GA Covered by SLA, versioned contract.
  • Beta Semver may break. Behind experimental=true flag.
  • Preview Design partners only. Undocumented.
