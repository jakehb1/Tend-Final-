One graph. Every layer of the stack.

tend is a four-layer platform: a governed ontology at the core, a connector fabric that feeds it, a policy engine that controls it, and an agent runtime that acts on it. Built to replace the fragile glue between your tools, not another one of them.

LAYER 01 / CORE

The ontology. Your business as a typed graph.

Define the entities, relationships, and lifecycle states your team actually operates on. Version them. Diff them. Migrate without downtime. Every other layer reads from here.

Types
Entities, relations, states, derived facts
Schema
Versioned, diffable, migratable
Latency
Sub-second reads on 10M+ entities
# schema / account.tend
entity Account {
  id: uuid
  name: string
  tier: enum("smb", "mid", "ent")
  health: computed { risk_score() < 0.3 ? "green" : "yellow" }
  owned_by: Contact via "primary_owner"
}

LAYER 03 / POLICY

Governance agents can't wriggle around.

Attribute-level permissions, row-level policies, versioned decision logic. Every read and write, from humans or agents, passes through the same rules. Full audit trail by default.

Access
Row + attribute level, ABAC
Audit
Immutable, queryable, replay-safe
Compliance
SOC 2 II · HIPAA · GDPR
# policy / agent_revenue.policy
policy agent_revenue {
  can read Account, Deal, Contact
  can write Deal.notes, Contact.last_touch
  cannot read Account.pii where region == "EU"
  rate: 120 ops/min, $50/day
}
LAYER 04 / ACT

Agents and workflows that share one source of meaning.

LLM-native agents consume the ontology as typed context, propose actions, and respect the same policies as humans. Event-driven workflows trigger on graph changes and write back to source systems.

Agents
Typed context, tool-call bounded
Triggers
On entity change, schedule, or API
Write-back
160+ destinations, retry + SLA
