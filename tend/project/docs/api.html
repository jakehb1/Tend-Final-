API reference.

tend exposes a REST API, a GraphQL endpoint, and a gRPC streaming interface. All three compile to the same typed surface and share the same policy enforcement. Choose by ergonomics, not by capability.

Authentication

All requests must be signed with a workspace-scoped token. Tokens are HMAC-SHA256 keyed, rotatable, and bound to an identity. Either a human (SSO-mapped) or a service account.

HTTPAuthorization: Bearer tnd_sk_live_a7f2…
X-Tend-Workspace: acme
X-Tend-Idempotency-Key: req_8f2c… # optional, 24h window

REST endpoints

GET/v1/entities/:type/:id
Fetch a single entity by id. Supports ?at=ISO8601 for point-in-time reads and ?depth=N for eager relation expansion (max depth 3).
POST/v1/entities/:type
Create or upsert an entity. Idempotent when X-Tend-Idempotency-Key is set. Returns the committed entity plus its lineage record.
PUT/v1/entities/:type/:id/fields
Partial update. Payload is a field-level patch; the runtime validates against the current schema version and enforces lifecycle transitions.
DEL/v1/entities/:type/:id
Soft-delete with configurable grace period (default 14d). Hard-delete requires the delete:hard capability and a signed operator approval.
POST/v1/query
Execute a typed query expression. Supports graph traversal, aggregation, temporal filters. Returns a streaming NDJSON body for result sets >10k rows.
POST/v1/agents/:name/invoke
Synchronously invoke a deployed agent against a supplied entity id. Respects all declared budgets and policies. Returns the run record including the typed write set and lineage.
GET/v1/runs/:id
Fetch a run record. Context snapshot, tool-call trace, model output, policy decisions, write set, cost.

GraphQL

The GraphQL schema is generated from your ontology. Every entity type produces query roots, mutation roots, and a subscription root for temporal change streams.

graphqlquery AccountWithContext($id: ID!) {
  account(id: $id) {
    id
    name
    tier
    health
    deals(where: { stage: OPEN }) {
      id
      amount
      stage
    }
    contacts(limit: 3, orderBy: LAST_TOUCH_DESC) {
      id
      name
      title
    }
  }
}

Webhooks

Subscribe to ontology events via signed webhooks. Delivery is at-least-once with exponential backoff (max 7 retries over 24h). Events carry the entity snapshot plus a lineage pointer. You never need a secondary fetch to interpret a delivery.

HTTPPOST https://your-endpoint
X-Tend-Signature: t=1713500000,v1=a7f2…
X-Tend-Event-Type: entity.written
Content-Type: application/json

Error model

Every error response uses a consistent envelope with a stable error code, a human-readable message, and a pointer to a lineage or policy trace when relevant. Error codes are listed in the appendix.

  }
}
