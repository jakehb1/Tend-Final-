Connectors & the ingest fabric.

180+ managed connectors, a thin SDK for everything else. All connectors feed the same ingest pipeline: extract → normalize → resolve → commit to ontology with full lineage.

Architecture

The ingest pipeline is four stages. Each stage is independently versioned, independently observable, and replayable from the stage boundary.

pipeline# extract → normalize → resolve → commit

source_system ──▶ extract   # connector-specific, cursored
                ──▶ normalize # schema map → canonical IR
                ──▶ resolve   # entity resolution (deterministic + ML)
                ──▶ commit    # transactional write, lineage, notify

Custom connectors

When the catalog doesn't cover your source, write a connector in ~150 lines. The SDK handles cursoring, retries, schema emission, and lineage. You implement extract().

connectors/internal_billing.pyfrom tend.connectors import Connector, Source, Cursor

@Connector.register(
    name="internal-billing",
    mode="near-realtime",
    emits=["Invoice", "Charge"],
)
class InternalBilling(Connector):

    def extract(self, cursor: Cursor):
        since = cursor.get("updated_at", default=cursor.epoch())
        for row in self.api.invoices(updated_since=since):
            yield Source.emit("Invoice", row, key=row["id"])
        cursor.commit(updated_at=now())

Lineage

Every entity in the ontology points back to the ingest run that produced it. Every ingest run points back to the connector version, the source cursor, and the extract payload hash. You can trace any field to its byte-exact origin.

queryacct = Account.get("acct_4102")
acct.tier.lineage()
