tend/docs/workflows

Workflows, sagas, and retries.

Workflows are typed, durable, event-driven. They subscribe to ontology change streams, compose agents and tools, and execute with transactional guarantees. Crashes resume at the last committed step.

Anatomy

workflows/renewal_intervention.pyfrom tend import workflow, ontology as o

@workflow(
    name    = "renewal-intervention",
    on      = o.Account.health.changed_to("red"),
    retry   = ExponentialBackoff(max=5, base=seconds(30)),
    timeout = hours(4),
    sla     = hours(1),
)
async def run(account: o.Account):

    verdict = await agents.renewal_risk.invoke(account)
    if verdict.risk < 0.6:
        return

    owner   = account.owner()
    channel = owner.preferred_channel() or "slack"

    draft   = await agents.outreach_drafter.invoke(account, verdict)
    approved = await human.approve(
        channel=channel, to=owner, draft=draft, sla=hours(1),
    )
    if not approved:
        return

    await tools.slack.post(channel=f"#csm-{owner.region}", text=draft.text)
    account.log("intervention_triggered", verdict=verdict.id)

Durability

Every await is a durable boundary. The scheduler persists workflow state after each awaited step. If a worker dies, another worker resumes the workflow at the next unfinished step. No lost work, no double-commits.

Exactly-once effects
Tools that have side effects (Slack post, Salesforce write) are invoked through an idempotency-keyed wrapper. Re-running a workflow after a crash will not duplicate the side effect.

Sagas

For multi-step workflows that span multiple systems, declare a compensating action per step. If a later step fails unrecoverably, the saga runs compensations in reverse order.

pythonasync with saga():
    invoice  = await netsuite.create_invoice(...)
    on_fail:   await netsuite.void_invoice(invoice.id)

    charge   = await stripe.charge(customer, amount)
    on_fail:   await stripe.refund(charge.id)

    await hubspot.mark_paid(deal)

SLAs & alerting

A declared sla is a soft deadline. The scheduler emits sla_at_risk at 80% and sla_breached at 100%. These are first-class events. Subscribe workflows to them to escalate, page, or downgrade gracefully.

Concurrency

By default, one workflow instance runs per (workflow, entity) key. Override with concurrency= to allow N parallel instances, or concurrency="serial" to force strict ordering.

Observability

Every run emits a span tree. The console renders a Gantt of steps with their durations, retries, and tool costs. Open a failed run to see the exact payload at the failure point.

shelltend wf runs --workflow renewal-intervention --status failed --last 24h
tend wf explain run_8f2c
