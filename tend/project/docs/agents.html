Agents, typed and bounded.

An agent in tend is a declared function with a typed context window, a bounded tool surface, and a replay-safe execution envelope. The runtime refuses any read or write the agent didn't declare at deploy time.

Anatomy of an agent

Every agent has five required declarations. The SDK decorator validates them at import; the runtime re-validates at deploy and at every invocation.

agent declaration@agent(
    name    = "expansion-signal-v2",
    reads   = [o.Account, o.Deal, o.Usage],
    writes  = [o.Account.expansion_note],
    tools   = ["slack.post", "hubspot.upsert_note"],
    model   = "claude-sonnet-4.5",
    budget  = Budget(tokens=8000, usd=0.05),
    timeout = seconds(30),
)

Typed context

Agents don't see rows — they see typed context. account.typed_context(depth=2) returns a validated view of the account, its direct relations, and their direct relations, with every field filtered through the active policy set.

pythonctx = account.typed_context(
    depth=2,
    include=["deals.open", "contacts.exec", "usage.last_30d"],
    exclude_pii=True,
)

# ctx is a typed object, not a blob.
# ctx.deals        : list[Deal]    (7 open)
# ctx.contacts     : list[Contact] (3 execs, PII stripped)
# ctx.usage.last_30d.events_per_week : 1_842

Tools

A tool is any callable that touches the world outside the ontology. Tools are registered per workspace with a JSON schema, a cost model, and a policy handle. The runtime refuses any tool invocation not listed in the agent's declaration.

CategoryExamplesCost model
notifyslack.post · email.send · pagerduty.pageflat per call
writehubspot.upsert · salesforce.updateflat + per-field
reasonreason · classify · extract · rankper-token, model-priced
humanapprove · review · escalateper-request SLA

Budgets & rate limits

Every agent declares a per-invocation budget (tokens + USD) and inherits a workspace-level rate limit. Exhaustion is a first-class signal, not a failure — the runtime emits a budget_exhausted event which workflows can subscribe to.

Budgets are enforced per-invocation
If your agent needs more than the declared budget, the right answer is almost always a workflow split — one agent drafts, a second critiques, a third commits. Stretching a single agent's budget is a design smell.

Replay & determinism

Every invocation is captured with: the typed context snapshot, the full tool-call trace, the model output, the policy decisions, and the final write set. Replay re-executes against the captured snapshot — useful for testing prompt changes against real historical inputs.

shelltend runs replay run_8f2c \
  --with-prompt ./prompts/renewal-risk-v4.md \
  --diff

Policies that bind agents

Three enforcement layers, applied in order. If any returns deny, the operation aborts with a structured PolicyDenied and the agent sees a typed exception — never silent data loss.

  1. Declaration check. Did the agent declare this read/write/tool at deploy time?
  2. ABAC. Do the caller attributes satisfy the row-level predicate?
  3. Rate & budget. Does the invocation fit in the declared envelope?

Common patterns

Watcher

A long-lived binding that fires on any change to a watched entity or its depth-N neighborhood. Use for risk scoring, anomaly detection, notify-on-threshold.

Drafter

A human-in-the-loop pattern: the agent produces a typed draft (a reply, a note, a forecast), writes it to a staging field, and blocks on a human.approve tool call before committing.

Reconciler

Consumes two sources of truth, produces a typed diff, writes a ReconciliationReport entity. Used heavily in finance ops.
